# Conversational NLP — milestone 1.0.1–1.0.3
Apply directly after React Master Data Management v1 (0.5.2), or overwrite the prior single-message NLP patch if installed. Back up code and MySQL first. Merge backend, frontend, docs; do not overwrite actual .env. The settings.py replacement assumes the original project configuration; merge the addition of apps.nlp manually if customized. Install requirements-nlp.txt, run check, migrate --plan, migrate, makemigrations --check --dry-run, and test apps.nlp.test_nlp. Restart both servers.

Append the configuration entries from .env.example to the existing root .env. Never expose the key in React or Git. Staff preview is available through React only when DEBUG=True. Select a fictional learner, read and acknowledge rules, start chat, clarify, edit/confirm or close. Learner route /learner requires a non-staff development Django user linked to an active LearnerProfile. Developers must provision/link accounts separately; real institutional authentication is out of scope. Existing management login is unchanged. Use only fictional text until privacy/retention/security review. No booking, faculty matching, real availability, approval or notification is performed.

Conversation records and drafts are stored in MySQL. Only the current session history, draft, active qualification, enrolled modules and their topics, timezone, and latest message go to OpenAI; no learner names or IDs are explicitly supplied, but free-text may contain personal details. The provider request sets store=False, not a guarantee of zero retention. Existing sessions can be reopened; confirmed and closed drafts are read-only. Expired or exhausted chats remain editable manually. One active session per account, including staff preview; close/confirm before starting a new one. Relative dates remain unverified text. Faculty preference is free text, not resolved. Topic selection optional if difficulty is explicit. Hard limit enforced in DB transaction, API rate uses DRF cache (development, not a distributed guarantee). Failed provider calls do not advance successful turn count and may incur charges. No daily or monetary cap; monitor provider usage. A row lock is held during provider call in this development version; replace with reservation/idempotency for production. No retention deletion process yet. Do not use live data. Automated tests supplied, run locally.
