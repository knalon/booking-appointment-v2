# Faculty Accounts & Workspace v1 (1.2.1)
Apply after faculty_scheduling_patch_v1. Merge backend/frontend/docs. No migrations or new dependencies. Run from backend: `python manage.py check`, `python manage.py provision_demo_faculty --confirm DEMO-ONLY`, `python manage.py test apps.scheduling apps.matching apps.nlp.test_nlp`. From frontend run `npm run build` then `npm run dev`. Open http://localhost:5173/faculty. For newly provisioned fictional F002 the username is faculty_f002 and password 1234, unless a collision required a suffix (see command output). Never use these credentials in production. Existing accounts are not changed. Use separate browser profiles for simultaneous logins; tabs in one profile share a session.

Faculty can read/write only their active profile's availability; management retains access. Learners and unlinked users are denied. The faculty profile already has a user link. Calendar uses seven day columns with stacked rounded cards, not a proportional time-grid. Weekly repeats expand to individual dated windows, 1–12 occurrences within existing 90-day horizon; edit/archive each independently. No historical windows are returned. Availability must be within working hours; busy windows may be outside those hours. Scheduling selection is still provisional; appointment booking, requests, notifications, feedback and coordinator login are not implemented here. No availability is seeded. Existing records preserved.

Check: faculty login, publish a future window, add busy period, edit/archive/restore, repeat weekly, confirm admin sees same windows, learner sees compatible slots, second faculty cannot access first faculty's schedule. Eight additional backend tests cover role and ownership, repeat/edit/archive/restore, mode/hours, inactive profile, unlinked users, demo provisioning. Full Django/MySQL tests and Vite build must be run locally.
