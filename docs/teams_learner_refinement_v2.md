# Milestone 1.4.2A refinement v2
Apply over Microsoft Teams Integration v1. Stop Django, React and worker, back up files/database, merge backend/frontend/docs. No migration required. No Power Automate changes.

Learner conversation now uses chat and confirmation only (consent and history retained). Corrections are conversational. Manual fallback editor and raw JSON are removed from learner UI only; backend validation and management records retained. If chat closes with missing details, close and start a new session or contact coordinator; no automatic case for an unconfirmed draft. Recommendation cards no longer show Why recommended; management audit details retained.

Both authenticated appointment participants and existing authorised staff can view a ready meeting link in either recipient mode. Other accounts cannot. Cancelled/rescheduled or non-ready links remain hidden. Previously created ready meetings need no recreation. Test invitations go only to configured test recipients, which may differ from the logged-in users; possession of the link does not guarantee Teams admission (lobby/tenant policy). Use controlled test accounts only.

## .env (project root)
Existing TEAMS_INTEGRATION_ENABLED=True enables creation. False disables new processing, not existing links. Existing POWER_AUTOMATE_MEETING_URL must stay private. TEAMS_TEST_MODE=True (default) uses TEAMS_TEST_FACULTY_EMAIL and TEAMS_TEST_LEARNER_EMAIL, both must appear in TEAMS_ALLOWED_EMAILS; DEBUG=True required. TEAMS_TEST_MODE=False uses registered FacultyProfile and LearnerProfile email addresses; test allowlist ignored. Optional TEAMS_REGISTERED_EMAIL_DOMAINS=educlaas.com restricts registered mode to exact comma-separated domains; empty allows any syntactically valid domain. Both modes validate distinct valid addresses. Only use registered mode after verifying real profile data and consent; no automatic email ownership verification or institutional OAuth implemented. A queued meeting created in the other mode is blocked rather than redirecting its recipients. Existing ready meetings retain their original mode. Resolve pending work before switching. Restart Django and worker after changes. Never put signed URL in frontend.
