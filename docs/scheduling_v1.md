# Scheduling v1 (1.2)
Baseline: Classification & Routing v4. Merge backend/frontend/docs into the existing project. Back up first. Run `python manage.py check`, `python manage.py migrate --plan`, `python manage.py migrate`, `python manage.py makemigrations --check --dry-run`, `python manage.py test apps.scheduling apps.matching apps.nlp.test_nlp`, then runserver. In frontend run `npm run build` and `npm run dev`. No new direct dependencies. On Windows ensure Python zoneinfo can access IANA time zone data (install tzdata if missing).

In React management > Faculty availability, select an eligible faculty from an existing recommendation, enter a future availability window within their working hours in their displayed time zone. Add a busy window to test conflict removal. Archive/restore windows. Availability is initially empty. In a separate learner browser, open the confirmed request, enter matching local availability dates and times, choose a duration if flexible (default 30), click Find compatible slots. Select a faculty/time. New searches clear previous provisional selections. Staff can inspect scheduling results through the matching review and download JSON.

15-minute start grid; 5–240 minute fixed duration; up to eight learner windows within 30 days; faculty windows within 90 days. Mode scores 1 for compatible mode, preferred availability 1, alternative .75. No points for unverified availability; no topic weight if no catalogue topic. Existing academic threshold and exact-topic preference retained. The full score is normalized by applicable weights. Slots are displayed in learner time zone. Explicit learner availability supersedes conversational date/time preferences for the search, which are shown as reference. No calendar sync; learner must exclude their own commitments; staff must enter faculty commitments. No automatic urgent priority queue. No appointment booking, holds, calendar invites, faculty self-service or production conflict locking. Multiple learners may provisionally select the same slot. Booking phase must revalidate and atomically reserve against real bookings. Stored scheduling runs are separate from confirmed NLP and academic results. Staff-only availability operations. Selection rechecks current eligibility and published windows but is not a guarantee. No live Django/MySQL or React build verified in author environment.
